# Política de segurança

## Versões com suporte

Só a versão em produção e a branch `dev` recebem correções de segurança. As versões estão nas [Releases](https://github.com/unb-mds/2026-2-Cerradinho-API/releases).

## Como reportar uma falha

Não abra issue pública para falha de segurança, porque ela fica visível para todo mundo antes da correção.

Use o [reporte privado do GitHub](https://github.com/unb-mds/2026-2-Cerradinho-API/security/advisories/new), na aba Security do repositório. Conte o que encontrou, como reproduzir e qual o impacto que você imagina.

O time responde em até 7 dias. Como é um projeto de disciplina feito por estudantes, não há prazo garantido para a correção, mas falhas confirmadas têm prioridade sobre qualquer outra tarefa.

## Escopo

Entram aqui a API, o site, o SDK, a CLI e a configuração de deploy deste repositório.

Ficam de fora o SIGAA e o site do RU, que são da UnB. Uma falha nesses sistemas deve ser reportada à própria universidade.

O Cerradinho só guarda dados que já são públicos nas fontes da UnB e não tem login nem guarda dado de quem usa a API ou o site.
